# Structured Feedback Form

## Goal

Replace the single free-text feedback input with a structured form that gives
the automated feedback-to-issue pipeline richer, more actionable data. The
form captures category, desired behavior, current behavior, and an optional
screenshot (bug reports only).

## User-facing changes

### Category picker

Segmented control at the top: **Bug Report** | **Feature Request**.
No default — user must choose before submitting.

### Text fields

| Field | Bug Report | Feature Request |
|---|---|---|
| What should happen | Required. Placeholder: *"Describe the expected behavior"* | Required. Placeholder: *"Describe the feature you'd like"* |
| What is currently happening | Required. Placeholder: *"Describe what's happening instead"* | Hidden |

Both fields: multiline, max 2000 characters each. Character counter appears at
1800+ characters (matching existing pattern).

### Screenshot (bug reports only)

- Visible only when **Bug Report** is selected.
- Single photo via `expo-image-picker` (library only, no camera).
- Thumbnail preview with a remove (×) button.
- Photo constraints: ≤10 MB, JPEG/PNG/HEIC (same as completion attachments).
- Uploaded to Supabase Storage bucket `feedback-media` at path
  `{user_id}/{feedback_id}/{uuid}.jpg`.

### Submit behavior

- Disabled until category is selected and "what should happen" has content.
- For bug reports, "what is currently happening" is also required.
- On submit: insert structured row → upload screenshot if present → navigate back.
- Existing rate limit (5/day) still applies.

## Database changes

### New migration: `20260518000000_structured_feedback.sql`

```sql
-- Relax body constraint (existing rows keep their data; new rows won't use body)
alter table public.feedback
  alter column body drop not null;

alter table public.feedback
  drop constraint feedback_body_check;

alter table public.feedback
  add constraint feedback_body_check
  check (body is null or char_length(body) between 1 and 2000);

-- Structured fields
alter table public.feedback
  add column desired_behavior text
    check (desired_behavior is null or char_length(desired_behavior) between 1 and 2000),
  add column current_behavior text
    check (current_behavior is null or char_length(current_behavior) between 1 and 2000),
  add column screenshot_path text;
```

### Storage bucket: `feedback-media`

- Private bucket (signed URLs only).
- RLS: insert allowed when `auth.uid()` matches the leading path segment;
  select allowed for the feedback row owner.

## Code changes

### 1. Migration file

`supabase/migrations/20260518000000_structured_feedback.sql` — SQL above plus
storage bucket creation and RLS policies.

### 2. `app/lib/feedback.ts`

- Export `FeedbackCategory = 'bug' | 'feature'`.
- Export `FeedbackDraft = { category, desiredBehavior, currentBehavior?, screenshotUri? }`.
- Expand `FeedbackValidationError` union with new kinds:
  `'no_category'`, `'desired_empty'`, `'desired_too_long'`,
  `'current_empty_for_bug'`, `'current_too_long'`, `'screenshot_too_large'`,
  `'screenshot_bad_type'`.
- `validateFeedbackDraft(draft): FeedbackValidationError | null` — replaces
  `validateFeedback`.
- `submitFeedback(draft)` — inserts structured row, then uploads screenshot
  if present and patches `screenshot_path`.
- `uploadFeedbackScreenshot(feedbackId, userId, uri): string` — reads file,
  uploads to `feedback-media/{userId}/{feedbackId}/{uuid}.jpg`, returns
  storage path.
- Keep `MAX_FEEDBACK_LENGTH = 2000` (applies per text field).

### 3. `app/app/feedback.tsx`

- Segmented control for category (two Pressable buttons, highlighted state).
- Two multiline `TextInput`s with conditional rendering and placeholders.
- Conditional screenshot section using existing `expo-image-picker` pattern
  from `completion/[id].tsx`.
- Thumbnail preview (100×100) with remove button.
- `ScrollView` + `KeyboardAvoidingView` wrapping the form.
- Submit calls `validateFeedbackDraft`, then `submitFeedback`.

### 4. `app/lib/__tests__/feedback.test.ts`

Tests for `validateFeedbackDraft`:
- No category → `no_category`.
- Empty desired behavior → `desired_empty`.
- Bug with empty current behavior → `current_empty_for_bug`.
- Feature with empty current behavior → valid (null).
- Over-length fields → `desired_too_long` / `current_too_long`.
- Screenshot file size / MIME validation.
- Valid bug draft → null.
- Valid feature draft → null.

## Out of scope

- Multiple photo attachments (single photo per decision).
- User-provided title (stays AI-generated by pipeline).
- Changes to the downstream pipeline Edge Function (`dispatch-feedback`).
- Video attachments for feedback.
- Camera capture (library picker only).
